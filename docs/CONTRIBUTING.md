# Contributing to B.E.N. OS — working proposal

B.E.N. exists to help humans create, cooperate and solve problems with care. We welcome proposed improvements from any contributor, subject to security, legal rights and the founder-approved contribution process. **This repository is not yet an authorised public open-source release; there is no active source-code redistribution licence.**

## Before making a change

1. Open or reference a non-sensitive GitHub Issue; explain the user problem and cite the relevant module ID and charter principle.
2. Make a focused branch rather than combining unrelated changes. Small changes reduce regression risk.
3. Discuss accessibility, data privacy, compute costs, creator agency and participant safety where relevant.
4. Do not include private member profiles, unpublished artworks without permission, medical history, abuse allegations, passwords or credentials in Issues/PRs.
5. Avoid unlicensed copyrighted datasets and unconsented model training. The work of artists and teachers is not raw material for appropriation.
6. Run `npm test`. For AI work, add a reproducible evaluation question and a fair human review procedure; never fabricate competence scores.
7. Request an independent reviewer. Repository maintainers may approve code quality, but no PR grants legal or policy authority.

## Creative education contributions

Each curriculum correction should identify the discipline, technique, level, why it helps learning, a rights-clear reference, an accessibility/safety alternative, and a practitioner reviewer. Contributor credits and agreed intellectual-property rights must be established before public licensing.

## Governance and dissent

Respectful disagreement is welcome, including criticism of founders, rules or AI decisions. Reviewers should explain declines with specific reasons. Any complaint about misconduct belongs in a separately permissioned human process, not public GitHub issues.

## Licensing

The founders must establish contributor rights, the chosen licence and an appropriate DCO/CLA process before accepting public code/assets. See `docs/OPEN_SOURCE_STRATEGY.md`. Contributors' original art remains theirs unless they explicitly agree otherwise.
