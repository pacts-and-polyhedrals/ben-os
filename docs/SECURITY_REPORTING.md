# Security & privacy reporting — prelaunch status

**Important:** No public security-reporting email or private vulnerability intake has yet been adopted or tested. Do not send vulnerabilities, sensitive member records, passwords, personal casework or private incident evidence through public GitHub Issues.

The founders must appoint at least two unconflicted technical contacts, establish and test a private reporting channel and back-up, publish realistic response times, coordinate disclosures and notify affected people as legally required. For a live incident, first protect accounts, rotate compromised credentials and preserve minimal evidence in permissioned storage; do not defer urgent protective action to a routine vote.

Before releasing the repository publicly, enable GitHub's supported private security advisory route or another tested confidential channel. Any vulnerability disclosure process should avoid retaliation against good-faith researchers and respect applicable law.

The local prototype has basic access controls and tests; it has NOT undergone independent penetration testing. Do not treat the absence of known incidents as a security certification.
